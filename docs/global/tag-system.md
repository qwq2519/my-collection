# 标签系统

## 基本规则

- **物理扁平**：标签是纯字符串，后端不做任何层级解析
- **逻辑层级**：用 `::` 作为命名约定模拟层级，如 `前端::React::hooks`，仅影响排序和展示
- **URL 和媒体各自独立的 tag 体系**，两套标签互不影响，笔记暂不支持 tag
- **大小写不敏感**：存储时统一转小写（输入 "React" 存为 "react"），避免重复
- **独立存储**：标签在 BuntDB 中有独立的注册表记录，不仅仅内嵌于实体的 tags 数组
- 总量千级上限

## 排序与展示

标签按字符串字典序排序。由于 `::` 的 ASCII 值，同一"前缀"下的标签自然聚在一起：

```text
前端
前端::react
前端::react::hooks
前端::vue
工具
工具::编辑器
```

前端可基于 `::` 分割渲染为树形视觉效果（缩进/折叠），但这纯粹是展示层行为，后端不感知层级关系。

## 生命周期

### 创建

**无独立的"新建标签"功能**。用户在编辑/新建书签或媒体文件时输入 tag：

1. 用户输入标签文本
2. 输入框提供**自动补全**（基于已有标签列表）
3. 若输入的标签在注册表中不存在，自动创建注册表记录（`count = 1`）
4. 若已存在，`count + 1`

### 移除

从实体上移除标签时，对应注册表的 `count - 1`。`count` 降为 0 时标签**不自动删除**，保留在注册表中（用户可能后续还会使用），需手动在标签管理页删除。

### 实体删除时的标签维护

删除带有标签的实体时，必须同步递减相关标签的 count。各模块的触发场景：

| 模块 | 触发场景 | 维护动作 |
|------|---------|---------|
| URL | 删除书签（单条或批量） | 遍历该书签的 tags，每个 url_tag count -1 |
| URL | 删除站点 | 遍历该站点的 tags，每个 url_tag count -1 |
| 媒体 | 扫描发现文件被删除 | 遍历该文件的 tags，每个 media_tag count -1 |
| 媒体 | 移除整个文件夹 | 遍历该文件夹下所有文件的 tags，批量递减 media_tag count |

**批量删除优化**：批量删除多条实体时，先汇总所有受影响标签的递减量，再一次性更新注册表，避免逐条写入。

这些操作与 BuntDB/Bleve 的写入在同一事务流程中完成（参见 [写入事务策略](./tech-stack.md#写入事务策略)）。若 count 因崩溃等原因漂移，可通过标签管理页的"重新计算"功能修正。

## 标签管理

提供独立的标签管理页面，URL 标签和媒体标签**分 Tab 管理**。

### 重命名

将标签 A 重命名为 B：

1. 校验 B 在同体系中不存在（若已存在则提示冲突，引导用户使用合并）
2. 遍历所有关联实体，将 tags 数组中的 A 替换为 B
3. 更新 BuntDB 注册表：删除旧 key，写入新 key（count 不变）
4. 同步更新 Bleve 索引

**不级联**：重命名 `前端` 不影响 `前端::react`，各标签独立。用户如需批量更新前缀，需逐一操作。

### 合并

将标签 A 合并到标签 B（A 消失，关联转移到 B）：

1. 遍历所有打了 A 的实体：
   - 若该实体已有 B → 仅移除 A（去重）
   - 若该实体没有 B → 将 A 替换为 B
2. 删除 A 的注册表记录
3. 重新计算 B 的 count
4. 同步更新 Bleve 索引

### 删除

删除标签 A：

1. 遍历所有关联实体，从 tags 数组中移除 A
2. 删除 A 的注册表记录
3. 同步更新 Bleve 索引

所有管理操作均需**二次确认**，展示影响范围（如"将影响 12 条书签"）。

### 重新计算 count

标签管理操作涉及多步写入（BuntDB + Bleve），崩溃可能导致 count 漂移。标签管理页提供**"重新计算"按钮**：

1. 遍历所有关联实体（URL 标签遍历站点 + 书签，媒体标签遍历所有 media_meta.json）
2. 统计每个标签的实际关联数，覆盖写入注册表 count
3. 清理 count 为 0 且用户未手动保留的标签（可选，需确认）

## 标签筛选

用户在 URL 模块或媒体模块中通过**多选标签**进行筛选：

- 从标签列表中勾选一个或多个标签
- 默认 **AND** 语义：选中 A + B，返回同时包含 A 和 B 的实体
- 查询走 Bleve keyword 精确匹配（多值 AND）
- 不支持 `前端::*` 前缀模糊查询，用户需明确选择具体标签
- **层级前缀查询**（低优先级，后续考虑）：点击父标签时自动展开并多选所有子标签，在前端层面实现

## UI

### 标签管理页

```text
[URL 标签]  [媒体标签]
🔍 [搜索标签...]
─────────────────────────────────────
前端::react        (12 个关联)  [重命名] [合并] [删除]
前端::vue          (8 个关联)   [重命名] [合并] [删除]
工具::编辑器       (5 个关联)   [重命名] [合并] [删除]
...
```

### 实体编辑时的标签输入

```text
标签: [react] [hooks] [+ 添加标签...]
                        ┌──────────────┐
                        │ react        │  ← 自动补全
                        │ react::hooks │
                        │ 新建: "rea..." │
                        └──────────────┘
```

- 输入时实时过滤已有标签，展示匹配项
- 选择已有标签或回车确认新标签
- 新标签自动创建注册表记录
