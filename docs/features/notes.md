# 笔记

## 需求

### 格式

Markdown 格式的短笔记，结构为 **title（必填）+ body**。

### 特点

- 轻量，不做复杂编辑器
- **不支持 tag**（暂时）
- 数据量少
- 与 URL 收藏和图片完全独立

### 笔记中的图片

- Markdown body 中可以插入图片
- 图片来源必须是 persist 目录下已有的图片，或复制粘贴时自动保存到 persist 目录
- 不支持引用外部 URL 图片或任意本地路径图片
- 粘贴图片统一走 `UploadService` 的 `note-image` scene（详见 [技术栈 - 统一文件上传](../global/tech-stack.md#统一文件上传)），具体前端拦截粘贴事件的技术方案在实现时确定

### 新建

- 列表页顶部提供**"新建笔记"按钮**
- 点击后在列表顶部插入一条新笔记，右侧自动进入编辑表单（标题 + Markdown 编辑器）
- 用户填写标题和内容后保存

### 编辑与保存

- 右侧为 Markdown 编辑器，支持编辑和预览切换
- **手动保存**：用户点击"保存"按钮或 Ctrl+S 触发保存
- **切换时自动保存**：切换到其他笔记或切换模块时，若有未保存的修改则自动保存
- 标题在编辑器顶部直接编辑

### 删除

- 右侧详情区底部提供删除按钮
- 删除操作需**二次确认**
- 删除笔记时同步清理 `persist/note-images/{note_id}/` 下的关联图片

### 孤儿图片清理

编辑笔记时移除图片引用后，`persist/note-images/{note_id}/` 下对应的文件会成为孤儿。清理策略：

1. **保存时 diff**：保存笔记时解析 body 中的图片引用列表，与 `note-images/{note_id}/` 目录下的文件对比
2. **发现孤儿时提示确认**：若存在未被引用的图片，弹窗展示列表，用户确认后删除
3. 用户取消则保留孤儿图片（下次保存时再次提示）

## 设计决策

### 存储

笔记数据存储在 BuntDB 中，全文搜索走 Bleve。详见 [技术栈与存储](../global/tech-stack.md)。

### 为什么不支持 tag

当前笔记数据量少，全文搜索已足够定位内容。后续如果笔记量增长再考虑引入 tag。

## UI

```text
│ 📝 会议记录      │                         │

│    ...           │                         │

└──────────────────┴─────────────────────────┘
```
